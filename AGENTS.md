# -

Рабочее пространство для анализа документов (PDF / Word / таблицы) с помощью агента.

## Идея проекта

Каждый анализ документов выполняется в **отдельном пространстве** — на своей ветке
`cursor/<краткое-описание>`. Ветка `main` держится чистой (только инфраструктура:
`requirements.txt`, `.gitignore`, `AGENTS.md`, `examples/`). Результаты каждого анализа
(скрипт + полученные таблицы) живут на своей ветке / в своём PR и не смешиваются с
другими задачами.

Пример такого анализа — ветка `cursor/merge-programs-table-ddf5`
(`merge_programs.py`): сравнение двух PDF с программами обучения и сборка общей
таблицы в Excel/CSV.

## Среда разработки

- Python 3.12, виртуальное окружение в `.venv` (не коммитится).
- Зависимости — в `requirements.txt`: PyMuPDF (`fitz`), pdfplumber, python-docx,
  pandas, openpyxl.
- Запуск любого скрипта: `.venv/bin/python <script>.py` (без активации окружения).

## Cursor Cloud specific instructions

- Зависимости ставятся в `.venv` автоматически update-скриптом при старте VM. Запускать
  скрипты нужно интерпретатором из окружения: `.venv/bin/python ...`.
- Системный пакет `python3.12-venv` необходим для создания `.venv` и уже присутствует в
  образе VM; в update-скрипт его добавлять не нужно.
- Шрифты base-14 PDF («helv» и т.п.) **не содержат кириллицу**. При генерации PDF с
  кириллицей встраивайте Unicode-TTF (например `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`),
  как сделано в `examples/analyze_pdf_table.py`. Извлечение текста из реальных PDF с
  кириллицей работает без дополнительных шрифтов.
- Входные документы и результаты держите в `uploads/` и `outputs/` — они в `.gitignore`,
  чтобы не засорять репозиторий бинарными файлами.
- Автоматических тестов и линтера пока нет; базовая проверка — `.venv/bin/python -m py_compile <файл>`.
- Быстрый прогон демо «hello world» (PDF → таблица → Excel/CSV):
  `.venv/bin/python examples/analyze_pdf_table.py`.
